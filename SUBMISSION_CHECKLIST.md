# Submission setup checklist — GROUP E

This folder contains drafts. **It does not create live GitHub Issues or a GitHub Project.**

1. Reuse the same repository from Assignment 1. Keep the existing `PROJECT_PROPOSAL.md` and verify its actual content.
2. Create the ten repository issues from `GITHUB_ISSUES_DRAFTS.md`; GitHub will assign real issue numbers. Set each to **Backlog** initially.
3. Create a GitHub Project, add all ten issues, and configure Status options: **Backlog**, **Ready**, **In Progress**, **Review**, **Done**.
4. Add a **Sprint** iteration field, configure a **two-week Sprint 1**, and create a board view named **Current Sprint**.
5. Give all three members access to the repository and Project.
6. Select the four issues corresponding to drafts 1–4; set **Sprint = Sprint 1**, **Status = Ready**, and assign their suggested owners. Leave the other six in Backlog.
7. Replace the placeholder issue numbers and URLs in `SPRINT_1_PLAN.md` with actual clickable links, and enter the real Project URL and two-week sprint dates.
8. Add or update `README.md` to link to `PROJECT_PROPOSAL.md`, `SPRINT_1_PLAN.md`, and the actual GitHub Project URL. Keep any useful existing README content.
9. Commit or open pull requests and merge the approved final Markdown files into **main**. Do not mark unfinished issues Done or invent contribution evidence.
10. Verify that all issue links and Project views are accessible to the instructor. Submit **both the repository URL and GitHub Project URL**.

**Required repository root:** `README.md`, `PROJECT_PROPOSAL.md`, `SPRINT_1_PLAN.md`.
